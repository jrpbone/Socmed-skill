# Layout families

Choose the layout from the relationship in the information, not from aesthetic preference.

## Convergence

Use when many inputs, steps, costs, or signals narrow into one decision or bottleneck.

Visual grammar: parallel lines, rays, or flows that approach a point; the output or decision sits beyond it. Use whitespace to make the threshold legible.

Avoid when the process is actually cyclical or branching.

## Concentric

Use for nested scope, why/how/what, maturity boundaries, or a core principle surrounded by execution layers.

Visual grammar: circles or fields that share a center. Direct labels should sit on the boundary they describe.

Avoid implying chronology unless the layers truly occur in sequence.

## Layers

Use for governance levels, risk containment, maturity, depth, or inheritance.

Visual grammar: nested or receding shapes whose size and position communicate scope. Labels should remain attached to the relevant boundary.

Avoid arbitrary nested shapes that do not encode a real inclusion relationship.

## Overlap

Use when the insight is in an intersection: shared ownership, combined costs, hybrid teams, or a system requiring multiple capabilities.

Visual grammar: two or three fields maximum; label the unique and shared regions directly.

Avoid decorative Venn diagrams where the overlap has no defined meaning.

## Binary comparison

Use for before/after, current/target, manual/agentic, or known/unknown.

Visual grammar: same scale, same chart type, same framing. Highlight the delta.

Never compare unlike units or crop scales to exaggerate the result.

## Annotated chart

Use when a real measured trend is the story.

Visual grammar: one chart, direct labels, one main annotation, necessary context and source. Remove legends when direct labeling works.

Avoid chart decoration that obscures the data.

## Real screenshot

Use when product behavior, interface, output, or workflow is the proof.

Visual grammar: authentic screenshot, restrained crop, one to three callouts, no fake window chrome unless it clarifies context.

Never generate a substitute interface.

## Selection test

Complete one sentence before rendering:

- “This is a **convergence** because …”
- “This is **concentric** because …”
- “These are **layers** because …”
- “The **overlap** matters because …”
- “The comparison is honest because both sides share …”
- “The chart proves … using …”
- “The screenshot proves …”

If the sentence is weak, the structure is probably wrong.
